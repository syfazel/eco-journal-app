seeing severe update/feed failures — "fix it properly, implement ALL
solutions TOGETHER, from infrastructure to in-app, make everything

## Layer 2 — transport + app data

EdgeRepository.kt:
- httpGetRetried: retries NETWORK errors only (500ms, then 1000ms);
  any HTTP error (incl. 404) returns immediately, never retried.
- Process-wide syncMutex: sync() and syncOnly() serialised (per-instance
  mutexes serialised nothing, since every caller builds a fresh repo).
- Offline fast path via isOnline() (already-declared ACCESS_NETWORK_STATE
  only): no network → fixed Failed("network") immediately, cache untouched.
- Overall 300s bound over the whole syncV3 pass; on timeout completed
  sections keep their transactions/hashes, the global clock does not
  advance, result is Partial — never a half-marked success.
- In-progress flag v51_sync_in_progress (1:<epoch> at start, 0 in a
  NonCancellable finally): a kill mid-sync leaves a stale flag the next
  pass overwrites; it is diagnosis state, never a lock; success hashes
  are still stored only on a section's complete success.
- Section failures degrade to FAILED/section_error and the pass
  continues (channel_typed, bundles, radar, nightly, gated loop).
- Global clock unchanged v5-P4 rule: required sections only (articles,
  shorts, market, channel_refs, channel_typed); UNKNOWN never blocks;
  failed optional sections record their own reason + timestamp and
  retry independently.
- Every section writes its v5.1 outcome line as it completes
  (v51_section_outcome: {code, fetched, missing, at, http}),
  plus v51_network_state and v51_seed_report, all best-effort, outside
  transactions, counts/codes/epochs only.
- Cache-first: sync only adds/updates; the only bulk delete is the
  formulas reference table; article rows are upserted or tombstoned
  (status = "retracted", bookmark fields preserved). One bad item file
  is skipped, counted, traced — never crashes the sync.
- Seed completeness verified against live manifest (281 = 249 + 32,
  164, 23) — no regeneration needed; seed runs with zero network and
  populates the feed from seed alone. Seed report now written on both
  the main path and the fast path.

SyncWorker.kt:
- enqueueLaunchSync(): one-time work with the same CONNECTED constraint
  as the periodic worker, so with no network it waits until connectivity
  returns (the network-change re-trigger, via the platform constraint —
  no receiver, no new permission, no expedited flag, which would need
  an undeclared foreground-service requirement). REPLACE gives each
  process start a fresh launch attempt; the repository mutex prevents
  overlap. Wired through schedule(), already called from
  EcoJournalApp.onCreate — no Application/MainActivity/manifest change
  needed. Periodic 15-min worker unchanged. doWork() try/catch →
  Result.retry() on unexpected throws.
- AppUpdateWorker.kt deliberately byte-identical: the 24h binary check
  already has its own timeouts/backoff; v5.1 scope is content transport.

Verifier edge/verify_v51_data.py: 84 checks, ALL PASSED, including the

## Layer 3 — feed UI staying + diagnostics UI

FeedViewModel.kt (new): retained holder, single source of truth for what
the feed shows. heldArticles/heldTyped/heldInstant are replaced ONLY by
non-empty Room emissions; there is deliberately no clear(). Rotation
survives via the ViewModel; process kill/restart restores from Room +
seed (holder starts empty on cold start).

FeedScreen.kt: display lists = held if non-empty, else live Room; every
emptiness decision reads the display lists, never the raw flows.
Branch-flip audit (each early return above the feed branch):
- urgent-all: was returned even if the rail had emptied → now guarded by
  railOrdered.isNotEmpty(), plus a reset effect clears showUrgentAll
  when the retained instant list empties.
- urgent rail: ordered from retained displayInstant (reorder only, never
  filter).
- format filter: reads retained displayTyped; filter-empty only when the
  retained list genuinely has none of that format.
- search: Room result authoritative when non-empty; empty Room result +
  non-empty held list → in-memory substring fallback over held lists.
- loading (seeding): spinner only when nothing is held; a held list
  renders instead.
- empty: reachable only when held empty AND Room empty (genuinely empty
  DB), with the existing cause lines (seed failure / offline / error
  code / no sync ever).
- syncing: never touched the list (verified); now additionally cannot
  clear anything, since all branches read display lists.
- update-check recomposition: banner only adds a row, never replaces
  the list (verified, unchanged).
- sync failure: last good list stays on screen with a one-line honest
  status (what happened + code) and exactly one next step (retry).

MainActivity.kt invite gate: a settings emission that lost BOTH flag and
hash after this process already saw a valid invite is treated as a
corrupt/transient read — session kept, suppression traced as branch
gate_held. It still locks when the hash is still present (genuine
revocation — EdgeRepository clears only the flag, keeps the hash), when
the user tapped re-lock (SettingsScreen sets
InviteLockSignal.manualLockRequested before clearInvite(); cleared on
the next valid invite), or when no invite was ever seen (fresh install).
A kept session is re-resolved by the next successful sync re-check and
is never presented as an empty feed. No invite code/hash handling
changed. Limitation: a corrupt store at cold start (before any valid
emission in that process) is indistinguishable from a fresh install, so
that case still shows the code screen.

DiagnosticsScreen.kt (display only): reads v51_section_outcome,
v51_network_state, v51_seed_report; outcome table with
code/fetched/missing/timestamp/HTTP; network/seed as flattened lines or
verbatim strings; absent/unparseable renders "not recorded", never a
crash or fabricated value. Fingerprint line 1 unchanged and still first.
Copy action copies the WHOLE displayed report verbatim, no truncation.
New branch names retained/gate_held.
